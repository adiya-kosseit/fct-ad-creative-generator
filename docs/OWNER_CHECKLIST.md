# Чек‑лист владельца аккаунта

Эти шаги делает только владелец аккаунта AWS и репозитория. Код их не заменяет: здесь пароли, ключи и приглашения, которые не должны попадать в Git и в Terraform state.

Отмечайте по мере выполнения.

## 1. Свой админ‑доступ вместо root

Terraform нельзя запускать с ключами root‑аккаунта.

1. Войти в консоль как root, включить MFA на root (IAM → Security credentials → Assign MFA).
2. IAM → Users → Create user → имя `adiya-admin` → «Provide user access to the AWS Management Console» → Attach policies directly → `AdministratorAccess`.
3. Войти под `adiya-admin`, включить MFA и ему.
4. IAM → Users → `adiya-admin` → Security credentials → Create access key → Command Line Interface (CLI).
5. На своём компьютере: `aws configure` → вставить ключ, регион `us-east-1`, формат `json`.
6. Проверка: `aws sts get-caller-identity` показывает `user/adiya-admin`, а не `root`.

## 2. Ключ Gemini в Parameter Store

Вариант через консоль:

1. Systems Manager → Parameter Store → Create parameter.
2. Name: `/fct-adgen/gemini-api-key`, Tier: Standard, Type: **SecureString**, KMS key: `alias/aws/ssm` (по умолчанию).
3. Value: ключ из Google AI Studio → Create parameter.

Вариант через терминал (ключ вводится скрыто): `./scripts/put-gemini-key.sh`

Проверка: `aws ssm describe-parameters --parameter-filters Key=Name,Values=/fct-adgen/gemini-api-key` показывает `Type: SecureString`.

Ключ создаётся вручную, а не через Terraform, чтобы он не оказался в файле state. Terraform‑код знает только имя параметра, а читать его может только роль Lambda. Участникам команды чтение явно запрещено политикой `fct-adgen-guardrails`.

## 3. IAM‑пользователи для команды

Пользователей, группы и права создаёт `terraform/bootstrap` (см. DEPLOY.md, шаг 2). После `apply` остаётся выдать пароли:

1. IAM → Users → `dayana` → Security credentials → Console sign‑in → Enable console access.
2. Autogenerated password, галочка «User must create a new password at next sign‑in».
3. То же для `raushan` и `arailym`.
4. Каждой отправить лично (не в общий чат): ссылку для входа из `terraform output console_sign_in_url`, имя пользователя и временный пароль.

Ключи доступа (access keys) владелец **не создаёт и не пересылает**. Если ключ кому‑то нужен для CLI, участница после входа создаёт его себе сама: IAM → Users → своё имя → Security credentials → Create access key. Политика `fct-adgen-self-service` разрешает это только для себя.

Что может каждая роль:

| Пользователь | Группа | Права |
|---|---|---|
| dayana | fct-adgen-backend | читать логи и метрики, смотреть и обновлять код Lambda `fct-adgen-*`, читать таблицу истории |
| raushan | fct-adgen-frontend | заливать файлы в бакет сайта, сбрасывать кэш CloudFront |
| arailym | fct-adgen-qa | ReadOnlyAccess на весь аккаунт для тестов и документации |

Всем запрещено: читать ключ Gemini, трогать Terraform state, удалять таблицы/бакеты/функции, запускать EC2, менять бюджет.

## 4. Доступ к репозиторию GitHub

1. Войти в GitHub под аккаунтом владельца репозитория.
2. `adiya-kosseit/fct-ad-creative-generator` → Settings → Collaborators → Add people.
3. Пригласить GitHub‑логины Даяны, Раушан и Арайлым (роль Write).
4. Каждая принимает приглашение из письма или на github.com/notifications. Приглашение живёт 7 дней.
5. Рекомендуется: Settings → Branches → Add rule для `main` → «Require a pull request before merging», чтобы правки шли через PR и было видно, кто что сделал.

## 5. Оповещения

1. В `terraform/envs/dev/terraform.tfvars` указать `alert_email`.
2. После `apply` придёт письмо от AWS Notifications → нажать **Confirm subscription**. Без подтверждения алармы не будут приходить на почту.

## 6. Бюджет
